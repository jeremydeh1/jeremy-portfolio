01

AWS Cloud Infrastructure Lab

I built a segmented AWS environment from the network up: a custom VPC, four subnets across two Availability Zones, a public Nginx server, and a private application server.

The goal wasn't just to get a website online. I wanted to understand the complete request path, why the application server could remain private, and how routing and security rules affected connectivity.

AWS VPC EC2 Linux Nginx Networking
Live project ↗ GitHub & documentation ↗
Architecture Request path
Public entry point

Public EC2 / Nginx

Nginx accepts HTTP traffic from the internet and forwards application requests to the private EC2 instance over the VPC network.

Network design

The VPC uses separate public and private subnets across two Availability Zones. The private application host does not need a public IPv4 address.

Security boundaries

Application traffic on port 8080 is limited to the intended source rather than exposing the application directly to the internet.

Linux services

Nginx handles reverse proxying while systemd keeps the private application service running across reboots.

Troubleshooting example

The service was running, but the site wasn't reachable.

Instead of changing settings at random, I worked outward through each layer of the system.

Service

First, confirm Nginx is actually running. There is no reason to troubleshoot AWS networking if the service itself is down.
